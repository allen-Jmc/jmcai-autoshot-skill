# 第二阶段：数字人口播视频

把"一张口播图片 + 一段配音"变成一条数字人口播视频。配音和文案由第一阶段产出，放在共用的项目目录里；这一阶段只负责人物视频，字幕、图形动画等包装在第三阶段做。

算力来自**本机的 JMCAI Comfypet 桌面端**（它内置 Workflow Bridge，默认 `127.0.0.1:32100`），数字人工作流固定用 `minimax-h3-copy-json`，跑在桌面端绑定好的算力目标上（本机 ComfyUI 或一台 4090 服务器）。**没有 API Key、没有会员档位、没有费用**——这是原版「RunningHub」的平替。

脚本路径相对本技能目录。项目目录（下文称 `workdir`）默认是最近一次的项目：

```
python scripts/voice/project.py latest        # 打印最近项目目录
```

需要的前置：`<workdir>/copy.txt`、`<workdir>/out/merged.wav`、`<workdir>/out/words.json`。缺任何一个，先回到第一阶段补上，不要自己估时间或另录配音。

## 红线

- **不改图片内容**：只允许按比例中心裁剪（并告诉用户裁了多少），不美化、不换背景。
- **不改文案**，提示词里的台词用原文。
- 提交前用一句话告诉用户段数（本地不产生费用，只是让他知道要跑多久）；用户这次的请求里已经明确说了"开始跑"就直接提交，否则等一个确认。

## 流程

### 0. 先要图片，再查环境

1. **先向用户要口播图片**，第一件事，其他都不先问。图片决定画幅、尺寸和提示词，所以放在最前面。
2. 查环境：

   ```
   python scripts/avatar/check_setup.py
   ```

   它检查三件事：桌面端在线、`minimax-h3-copy-json` 已启用、有可用的算力目标。

   - 退出码 3：桌面端没连上，或工作流没启用/没有算力目标。把脚本输出的引导话**原样**转给用户并停下等待，让他去桌面端处理。**不要自己去扫端口、猜地址、改桌面端配置**；端口不是 32100 时让他告诉我，我设 `JMCAI_BRIDGE_URL`。
   - 退出码 0：继续。想改并行段数（默认 1，单卡串行最稳）用 `--set-concurrency N`。

### 1. 处理图片

```
python scripts/avatar/prepare_image.py --image <图片> --workdir <workdir> --mouth-box x0,y0,x1,y1
```

`--mouth-box` 是**你看图后给出的嘴的位置**（占画面宽高的比例，例如 `0.42,0.46,0.58,0.58`），成片质检用它定位嘴部；先看一遍图再写，不要瞎填。

- 在 16:9、9:16、1:1、3:4、4:3、21:9 里选最接近的一档，把图按该比例做最大范围的中心裁剪（不拉伸），存成 `avatar/image.png`。
- 这里算出的目标尺寸（如 16:9 → 1376×768）只用于估算和裁剪参考；**实际输出分辨率由工作流按画幅自己决定**（16:9 实测为 1920×1088），拼接时以实际片段为准。
- **必须看一眼 `avatar/image_crop_check.jpg`**（原图上画了裁剪框）：头顶、手被裁到了就告诉用户，让他换图或自己先裁；没问题再继续。图片比目标小会被放大，要把脚本的提示转告用户。
- **同时看图片里的姿态**（每一段的开头和结尾都会回到这张图的姿态）：理想是正面、双手自然放在身前或桌面、没有夸张表情；如果是"双手抬在空中、嘴正在说话"的瞬间图，告诉用户一句"这张图双手抬在空中，建议换成自然放置的图，效果会更稳；也可以直接用这张"，由用户决定，不替他拒绝。

### 2. 分段

```
python scripts/avatar/plan_segments.py --workdir <workdir>
```

只设"每段最长 14 秒"：全长不超过 14 秒就整段；否则取 ceil(总长/14) 段，在配音的**停顿**处断开，切点尽量均分，不设最短限制。找不到合适停顿才依次放宽（多一段、句末标点、词边界），宁可多一段也不切在句子中间。结果写入 `avatar/plan.json`，每段音频切成 `avatar/seg_NN.wav`。

### 3. 写提示词

先读 `references/avatar/prompt-rules.md`，再按它做三件事：看图（用 Read 工具看 `avatar/image.png`）、通读 `copy.txt`、看 `plan.json` 的每段时长和逐字时间。然后写 `avatar/prompt_src.json`：

```json
{"image_type": "图片类型（必填，A/B/C/D/E 之一，可叠 +持物左 / +持物右 / +旁物 / +非中性，如 \"C+旁物\"）",
 "scene": "画面描述（看图写：人物的发型、衣着、佩戴物；位置和姿态；背景左右两侧有什么）",
 "hands": "双手的原姿态（分别写「画面左侧的手」「画面右侧的手」在图中的位置、掌心朝向、手指状态）",
 "posture": "身体的原姿态（上身朝向、肩线、头的位置；可选，建议写）",
 "lines": ["第1段台词原文", "……"],
 "motions": ["第1段动作编排（每行一个节拍：起–止「词」：动作，两只手都要写）", "……"]}
```

**`image_type` 必填**，脚本按它放宽或收紧校验（A 近景不写手；B/D/E 要求写双手和身体动作；`+持物` 的那只手不提示"弱动作"；`+非中性` 要求末拍把身体回正）。判断标准和写法见 `references/avatar/prompt-rules.md`。

固定镜头首行由 `build_prompts.py` 自动注入（`<固定镜头，无运镜>`，防模型把动作做成推拉变焦），你只写上面五项。

要点（细节和理由见 `references/avatar/prompt-rules.md`）：

1. **不写任何与嘴部有关的描述**（硬规则）：微笑、笑意、嘴唇、口型、换气、表情、情绪形容词一律不写。嘴怎么动由工作流和音频负责。情绪只能写成动作。
2. **先从图里读出手能去哪**：能落在哪（桌面、腿上、腰侧、画面下方）、手边有什么能碰、活动范围多大。动作只从这里面选。
3. **每个节拍两只手各有角色**：主手做主要手势；副手做一件自己的、看得见的事（落到某处、托着、叉腰、收到身前、在落点上轻点），不是"同时轻轻摆动"；想歇着就落到一个地方。两只手轮流当主手。
4. **动作跟着这句话的性质选**：平静处让手落下再抬起；强调、吐槽处用有落点的动作（轻拍桌面、一拍手、拳头敲掌心）；数量和对比用比量；有起有落、有大有小、不重复。
5. **不用比喻**：不写"像拿着话筒""像捧起东西"，模型会把那样东西画出来；直接写手怎么动。脚本会拦。
6. **身体也要动，但只动左右和上下**：每两三个节拍带一次肩膀或头的小动作；宁可少不可大，段尾回正。**不写前倾、后靠、探身，手不伸向镜头**——模型会把它做成推近拉远，画面和背景跟着出错；推近、拉远、放大这类运镜一律留给包装阶段用代码做。脚本会拦。
7. **逐段读着写**，不要用按关键词套动作的脚本批量生成。

```
python scripts/avatar/build_prompts.py --workdir <workdir>
```

脚本分两类：`image_type` 缺失或写错、格式和时间、关键词不在台词里、嘴和表情词、具体手指数、触碰佩戴物、视线离开镜头、首尾没有回到原姿态这些会拦，按提示改到通过；两只手的写法（副手只有弱动作、主手总是同一只、整段没有起落、手势重复）只给提示，不拦。通过后提示词在 `avatar/prompts/`。

### 4. 预览，再提交

```
python scripts/avatar/run_avatar.py --workdir <workdir>          # 预览：不提交
```

预览会列出画幅、段数、每段时长和提示词字数。本地不产生费用，但数字人很慢（见下），确认后提交：

```
python scripts/avatar/run_avatar.py --workdir <workdir> --yes
```

- **默认 1 段串行**（单张卡），多段依次跑。要并行用 `--concurrency N`。
- **一段要跑 4–5 分钟**（7 秒的片子实测：低分辨率采样约 199 秒 + 过渡 9 秒 + 高分辨率约 60 秒）。第一次跑还要加载模型，更久。
- **分辨率用 `--megapixels` 控制**（`1.0` 快、适合抽卡，`2.0` 高清，不写就用工作流默认的 1.5）。⚠️ **全片各段必须用同一个 `--megapixels`**：分辨率不同，模型输出的构图（人物在画面里的大小）也不同，拼接处会明显跳变，而这不是裁帧能解决的。混用过的片子只能重跑统一。
- **桌面端等远端输出有上限（实测约 180 秒）**，超过就把这次运行标成失败（`等待 ComfyUI 输出超时。`），但**任务在算力目标上还在跑**。脚本认得这种情况，会自动用运行记录里的 `promptId` 直接去算力目标取结果（`--timeout-min` 控制这段等待，默认 45 分钟）。所以你看到"桌面端等超时了，改为直接查 prompt …"是正常的，不是出错。
- **提交前会拿桌面端的实时 schema 核一遍参数**（枚举值、必填项）。不通过会当场报出来，不会白跑一轮——不核的话，算力目标上节点校验失败会把输出整个丢掉，而桌面端仍报"成功"。
- **重试**：提交被拒（连接/队列）退避 20 秒重试，最多 12 次；运行失败先判类型，参数/权限类直接停下报告，其余退避 15 秒后重提交一次（`--retries`，默认 1）。
- **断点续跑**：运行号一提交就落盘到 `result.json` 的 `pending`。脚本被中断、超时或部分段失败后，直接重跑同一条命令：已成功的段沿用，仍在跑的运行会被续上，只补真正失败的。想强制重做某段才用 `--only <段号>`。

**重跑与补救**（`--only <段号>` 时生效）：

- **同样的输入重跑通常得到同样的结果**。要让结果变，先换一样东西：`--seed random`（每段各取一个随机种子）换种子，或改 `prompt_src.json` 后重跑 `build_prompts.py` 改提示词。
- **单段补救上限 2 次**（记在 `result.json` 的 `retakes`）。到上限会停下并说明，要突破得显式加 `--force-retake`——避免在同一个坑里反复烧时间。
- **旧片段不丢**：重跑前把上一版收进 `avatar/clips/takes/`（默认开，`--no-keep-take` 关）。重跑失败时旧结果仍保留，不会把工程搞成"既没新片也没旧片"。
- 先遮盖，再重跑：画面某几秒有问题，优先交给第三阶段包装盖过去，比重新生成划算。

### 5. 拼接与质检

```
python scripts/avatar/finalize.py --workdir <workdir>
```

每段按音频时长裁掉模型补的多余帧再拼接；**声音直接用项目里的原配音**，不用回传的音轨；输出分辨率以实际片段为准（16:9 是 1920×1088）。质检项：分辨率、时长与配音差、黑帧和冻结候选，并生成 `avatar/seams.png`（每个接缝前后各两帧），**用 Read 工具看一眼**有没有跳变、变脸、变构图。

同时把每处接缝的帧间差写进 `avatar/seams.json`。**接缝的 MAD 天然高于段内相邻帧**（换段本来就是两张画面），所以脚本不拿它跟段内比，而是**在接缝之间互相比**：哪一处比全片接缝中位数高出 1.8 倍以上，才单独列出来。列出来的那一处通常是该段首尾姿态没回到原位，改那一段的动作编排后用 `--only` 重跑；各段之间均匀就不用管——包装阶段的小窗会把这些切点盖住。

- **各段分辨率不一致会明确告警**（`⚠️ 各段分辨率不一致：…`）。这就是上面说的构图跳变，只能重跑时统一 `--megapixels`，裁帧救不了。
- **`--trim-frames` 默认 0（关闭）**：上游云端工作流裁 4 帧接缝更干净，但**本机实测无效**——0~32 帧范围内接缝跳变 MSE 波动不到 3%，因为本机跳变的主因是构图不一致，不是启动帧。换工作流时可以打开再试。
- 另外产出两份**最终版资产**，第三阶段优先用它们，不要再回头读 `out/` 下的中间文件：`avatar/words_final.json`（成片逐词时间，附裁帧信息和每段边界）和 `avatar/voice_final.wav`（从成片提出的人声轨，48kHz 双声道，与画面严格同长同轴）。

再做内容质检：

```
python scripts/avatar/qa_video.py --workdir <workdir>
```

它输出一张逐段表、一张嘴部逐秒图、`avatar/anomalies.json`（异常时间段，给包装遮盖用）和 `avatar/qa.json`（逐段指标与判定）：

| 指标 | 怎么算 | 用来判断 |
|---|---|---|
| **清晰度** | 每段抽 8 帧算拉普拉斯方差取中位数 | 低于 110 或低于全片中位数的 80% → 这一段糊了 |
| **嘴动量比** | 段内说话时嘴部帧差 ÷ 全片中位数 | 远低于 1 说明说话时嘴几乎不动 |
| **嘴不动秒数** | 段和"嘴不动"区间重叠了几秒 | 连续 ≥3 秒才算问题 |
| **左右手静止率** | 段内动作量 <0.8 的帧占比 | 只提示，不重拍 |
| **段间色差 ΔE** | 段背景色与各段中位色的 Lab 距离 | 只提示，交给包装遮盖 |
| **逐秒色彩** | 每秒背景色和输入图片比 | 色相偏转 >20° 或彩度 <55% 记异常 |

**`qa.json` 里的 `retake` 就是"该重拍的段"**，判定分工是刻意这样定的：

- **清晰度不够 → 重拍**。糊是遮盖盖不掉的。
- **段内连续 ≥3 秒嘴不动 → 重拍**，但要先改提示词，光换种子通常没用。
- **手整段静止 → 只提示，不重拍**。这是提示词的问题，重拍十次还是同一双手。
- **段间色差大 → 只提示**。重拍 5 分钟，遮盖 0 成本。

> 嘴部区域如果是**估算**出来的（既没有 `mouth_box` 也没有人脸检测），脚本**不会**据此判重拍，只提示。区域没框到嘴时动作量天然接近 0，那样判出来的"闭口"是假的。

**嘴部框按段校正，不是全片一个。** 数字人各段的人物位置会漂移（实测一条片子段 3 的脸右移 148px、嘴框偏了 242px），而 `image_info` 里的 `mouth_box` 是按底图量的、只对最接近底图姿态的那段成立。框脱靶时测到的是脸颊，"嘴动量"会从 11.6 掉到 3.1，看着像"说话时嘴不动"——**据此重拍就是白等 4–5 分钟重跑一段没问题的片子**。所以脚本每段在段首附近重新检脸、按脸推嘴框，每段实际用的框和来源都写在 `qa.json` 的 `mouth_region_per_segment` 里。看到"嘴动量比偏低"先去看这一项：框偏了是测量问题，不是表演问题。

这套判定是数字人闭环的分诊台，判错一段的代价是白等 4–5 分钟，所以它有自己的离线回归测试（改过阈值或判定逻辑就跑一遍）：

```
python tests/avatar/test_qa_verdict.py        # 49 项：清晰度/嘴动/人脸/色彩/嘴框定位各类边界
```

### 5.5 自动重拍闭环

```
python scripts/avatar/auto_retake.py --workdir <workdir>          # 预览：跑一遍质检，说要重拍哪几段
python scripts/avatar/auto_retake.py --workdir <workdir> --yes    # 真跑
```

它把 `qa.json` 的 `retake` 变成动作：**换种子重拍那几段 → 重新拼接 → 再质检**，最多两轮。三条边界是为了不把时间烧在没用的重拍上：

- 单段最多重拍 2 次（沿用 `run_avatar` 的上限），到顶就停，提示改提示词；
- 一轮要重拍的段数超过 3 段、或超过全片一半 → 停。**这么多段一起不达标，是提示词或底图的问题，不是抽卡运气**，继续抽只会一直错；
- 旧版本一律保留（`clips/takes/`），最后按清晰度和嘴动量**挑最好的拼回去**——抽卡可能越抽越差，不能默认"新的更好"。

**跑之前先跟用户说一句**：这是循环提交，一段 4–5 分钟，最多 3 段 × 2 轮，可能连着跑半小时。用户这次已经说了"自动修到好"就直接跑，没说就先报一句。

只要挑版本、不重拍时用 `--pick-best`。

### 5.6 手势的反馈回路

`qa_video.py` 量出来的"每段左右手各有几成帧近似静止"，会回到 `build_prompts.py`：

```
python scripts/avatar/build_prompts.py --workdir <workdir>
```

它默认读 `avatar/qa.json`，把上一轮**哪一段的哪只手没动起来**直接列出来，并写进 `avatar/prompt_feedback.json`。改 `prompt_src.json` 里那几段时对着这张清单改——不是让人凭空写得更细，是让上一轮的数据指出哪一段写得不够。加 `--feedback none` 关掉。

此外用 `scripts/packaging/contact_sheet.py` 每 2–4 秒抽帧，看手有没有遮脸、表情是否夸张、手形是否别扭。

**哪些不用补救**：段与段之间颜色有小幅跳变、灯光颜色有自然的变化、手偶尔停一下，都属于可以接受——切点都在说话的停顿处，正常剪辑也会有这种跳变。这些情况在交付时提一句即可。只有嘴不动、整段变成另一种色调、画面里多出明显不该有的东西、手形或人物明显出错时才补救。

**先考虑遮盖，再考虑重跑。** 重跑很慢，而且同样的输入常得到同样的问题。`anomalies.json` 里的异常可以在包装时遮盖掉：异常出现前人物缩到右下角小窗（嘴不动这类人物本身的问题则暂时隐藏人物），主画面放这几句话的要点卡，异常过后再回到全屏。只有下面这些情况才重跑：异常在片头 3 秒内、落在用户专门设计的动作上、或遮盖总时长会超过全片约 40%。

每段最多补救 2 次（脚本记在 `result.json` 的 `retakes`，到上限会拦下并提示，要再试得加 `--force-retake`），仍不行就如实报告。

### 6. 小结并进入下一阶段

一条龙流程里这一步不是终点：用下面的要点向用户报一句进度（尤其是 `anomalies.json` 里有没有要遮盖的时间段），然后进入包装阶段；用户只要人物视频时才在这里停下。

先给结论，再给依据，用中文：

- 一句话结论：成片路径、尺寸、时长、几段。
- 分段情况：每段时长和断在哪（停顿还是别的）。
- 质检结果：脚本的几项、接缝图、嘴逐秒图和抽帧的观察，每个问题给出时间点。
- **没验证的**如实写：口型是否对准、手势细节、人物是否前后一致——脚本和静帧都判断不了，请用户播放确认。

产物都在 `<workdir>/avatar/`：`final_avatar.mp4`、`words_final.json`、`voice_final.wav`、`plan.json`、`prompts/`、`clips/`（各段原始视频，重跑的旧版本在 `clips/takes/`）、`result.json`（运行号与补救次数 `retakes`）。

## 失败时怎么办

| 现象 | 做法 |
|---|---|
| 缺 `words.json` / `merged.wav` | 先回到第一阶段 |
| 退出码 3 | 桌面端没连上或工作流没启用，走第 0 步 |
| 退出码 4 | 桌面端在算力目标上执行失败，把原始错误转给用户 |
| "运行报成功但没拿到视频文件" | 算力目标上节点校验失败（多半是某个枚举值不在候选列表里），ComfyUI 把输出丢了但桌面端仍报成功。按报错里的提示去算力目标的 ComfyUI 日志搜 `Failed to validate prompt`；同时用 `check_setup.py` 确认工作流 schema 是新的 |
| "桌面端等超时了，改为直接查 prompt …" | 正常路径，不是错误；脚本会一直等到算力目标跑完 |
| 某段失败 | 脚本已自动重试一次；仍失败就报告原始错误 |
| 脚本中途被打断 / 超时 | 直接重跑同一条命令，会续上已提交的运行，不会重复提交 |
| 接缝有跳变 | 看 `seams.png`，指出是哪个接缝；通常是该段首尾姿态没回到原位，改那一段的动作编排后用 `--only` 重跑 |
| `⚠️ 各段分辨率不一致` | 各段用了不同的 `--megapixels`，模型输出的构图不同，接缝必跳。只能统一 `--megapixels` 重跑，裁帧无用 |
| `image_type：必须填图片类型` | `prompt_src.json` 少了 `image_type`，看图判断景别后补上 A/B/C/D/E |
| 提示"片段实际分辨率 W×H" | 正常：本地工作流按画幅自己出分辨率，拼接以它为准 |
| `段N 已经重跑过 2 次` | 单段补救到上限。先换种子（`--seed random`）或改提示词；确实要再试加 `--force-retake` |
| `auto_retake` 说"这一轮要重拍 N/M 段，超过上限" | 这么多段一起不达标，是提示词或底图的问题，不是抽卡运气。先按 `prompt_feedback.json` 改写法，或把其中几处交给包装遮盖 |
| `qa_video` 说"整片清晰度偏低" | 不是某一段的问题：查底图分辨率和 `--megapixels`（1.0 快但软、2.0 高清）。别逐段重拍 |
| `qa_video` 说"嘴部区域按人物居中估算" | 嘴部判定不可信，不会据此判重拍。用 `prepare_image.py --mouth-box` 写进嘴的位置再跑 |

工作流契约、已验证数据和没验证的事项，见 `references/avatar/jmcai-notes.md`；Bridge 的通用契约见 `references/voice/api-notes.md`。
