# 数字人工作流：契约与验证状态

记录日期：2026-10-14。"已验证"指在本机用真实运行实测过。

Bridge 的通用契约（提交返回 202、loopback 直接传本机路径、状态机、直连目标兜底）见 `references/voice/api-notes.md`。这里只写数字人这一套。

## 工作流 `minimax-h3-copy-json`（▶▷MiniMax H3-数字人）

暴露参数（桌面端实测）：

| alias | 类型 | 必填 | 说明 |
|---|---|---|---|
| `audio` | audio | 是 | 驱动音频，**本机绝对路径**直接传 |
| `image` | image | 是 | 正面人像底图，本机绝对路径 |
| `prompt` | string | 是 | 动作与神态描述（本技能拼好的四段式提示词） |
| `aspect_ratio` | enum | 否 | 默认 `9:16 (Portrait Widescreen)`，8 个候选见下 |
| `seed` | int | 否 | 默认 42，固定可保持一致性 |

`aspect_ratio` 的 8 个候选值（**必须逐字一致**）：
`1:1 (Square)`、`2:3 (Portrait Photo)`、`3:2 (Photo)`、`3:4 (Portrait Standard)`、`4:3 (Standard)`、`9:16 (Portrait Widescreen)`、`16:9 (Widescreen)`、`21:9 (Ultrawide)`。

**注意**：`common.py` 的 `ASPECT_RATIO_CHOICES` 里的字符串要跟这张表一致。写错了不会当场报错——算力目标上的 `ResolutionSelector` 节点会校验失败、把输出整个丢掉，而桌面端仍然报"成功"。

产物：一个 mp4（16:9 实测 1920×1088、24 fps、H.264 + AAC 单声道 24 kHz）。
输出分辨率由工作流按画幅自己决定，**不接受宽高参数**；`finalize.py` 以实际片段分辨率为准。

## 耗时（实测）

| 环节 | 耗时 |
|---|---|
| 低分辨率采样 | 约 199 秒 |
| 低→高分辨率过渡 | 约 9 秒 |
| 高分辨率采样 | 约 60 秒 |
| 合计（7 秒的片子，模型已热） | **约 4–5 分钟** |
| 首次冷启动 | 另加模型加载（数十秒） |

**结论**：桌面端等远端输出的 180 秒上限一定不够，必须走直连兜底（`run_avatar.py` 已内置）。

## 已验证

- 16:9 画幅跑通，输出 1920×1088、24 fps、H.264 High、AAC 单声道 24 kHz，9.42 秒 / 226 帧（早期直连实测）。
- 逐字色彩检测的标定（2026-10-04，一个人物、四个版本）：正常的秒，背景色相相对图片偏转 ≤12°、彩度是图片的 0.9–1.7 倍；整幅变青或变黄绿的秒色相偏转 26–134°；褪成灰白的秒彩度 ≤0.4 倍。阈值取 20° 和 0.55。另一个人物（背景本身是紫红色）全片色相偏转 5–7°、彩度 1.1 倍，没有误报。背景里局部多出东西（架子上多出亮屏）这种检测不到。
- 每个节拍都写两只手、不让任何一只手静止：近似静止的帧占比从 37%/41% 降到 25%/19%。
- 通用要求由工作流内置模板加入、技能只发送画面描述/双手/台词/动作编排之后：同一条 55.4 秒的片子 5 段全部一次成功；每段说话时嘴动量 6.25–7.26，没有出现嘴不动的段；左右手静止帧 16% / 11%；各段色差 ≤0.8；接缝连续。只跑了这一条。
- 两条片子里各出现过一段"说话时嘴闭着或几乎不动"（约 10 秒），音频本身没有异常；成片仍要看嘴部逐秒图确认。
- 出现过提示词里没有写的手形（双手握拳），属于模型自行发挥，需要人看。

## 没验证的

- **单段 14 秒在 16:9（1920×1088）下的显存**：实测跑过的是 7.3 秒和 9.42 秒。14 秒可能爆显存；失败只会报告，不会自动换目标。
- **非 16:9 画幅**：1:1、4:3、9:16、21:9 只是按候选值映射，没有实际跑过。
- **多段并行的行为**：默认串行；`--concurrency` 在单卡上只会互相排队，没有实测收益。
- **重试与续跑逻辑**：只在真实超时（桌面端 180 秒）这一种情况上验证过直连兜底；其余分支是按关键词推测的。
- **`seed` 改变对一致性的影响**：只用过默认 42。
