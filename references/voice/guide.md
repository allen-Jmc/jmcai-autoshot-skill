# 第一阶段：配音（用用户自己的声音）

把用户给的文案，用用户自己的声音念出来，并留下后续环节（分段、数字人）要用的逐词时间。参数已固定，流程只有一条路，目标是让用户少说话、少操作。

算力来自**本机的 JMCAI Comfypet 桌面端**（它内置 Workflow Bridge，默认 `127.0.0.1:32100`），工作流跑在桌面端绑定好的算力目标上（本机 ComfyUI 或一台 4090 服务器）。**没有 API Key、没有计费、不需要在本机装识别工具**——这是原版「阿里百炼 DashScope」的平替。

固定的东西在 `scripts/voice/common.py` 里：48k wav、每段最多 1000 字、默认串行 1 路（本地单卡）、默认指令（"像朋友聊天一样自然随意的口语，不要播音腔，语速较快，句与句之间保留自然的停顿，语气轻松带笑意"）。**语速用"较快"**。

## 桌面端里用到的 4 套工作流

| 工作流 id | 名字 | 用途 | 关键参数 |
|---|---|---|---|
| `qwen3-tts-_api` | Qwen3-TTS 声音克隆 | **默认**：用参考音频的音色念文案 | `audio_4`(参考音频)、`text`、`seed`、`language_2`、`ref_audio_max_seconds` |
| `qwen3-tts-_api-2` | Qwen3-TTS 预设音色 | 不想给样本时，用内置音色 | `text`、`speaker`(Vivian/Serena/Uncle_Fu/Dylan/Eric/Ryan/Aiden/Ono_Anna/Sohee)、`language`、`instruct`、`seed` |
| `qwen3-tts-voicedesign-_api` | Qwen3-TTS 声音设计 | 用一句自然语言描述造一个音色 | `text`、`instruct`(音色描述)、`language`、`seed` |
| `qwen3-asr-_api` | Qwen3-ASR 字级时间戳 | 逐字时间 + 文字核对 | `audio_1`、`language` |

用哪一套由 `voice.json` 的 `mode` 决定（`clone` / `preset` / `design`），也可用环境变量 `DH_TTS_MODE` 覆盖。**默认 `clone`。**

**重要差别**：只有 `preset` 和 `design` 两套接受 `instruct`（情绪/语气指令）。`clone` 那套**没有**指令参数，所以 `[excited]` 这类方括号情绪标签在 clone 模式下会被原样念出来——脚本会自动剥掉它们（`common.strip_tags`）。也就是说：

- **clone（默认）**：情绪来自参考音频本身，标签一律剥掉，不需要写 `emotions.json`。
- **preset / design**：情绪靠 `instruct` + 句首标签，`emotions.json` 照常用（见第 4 步）。

## 项目目录（文案缓存）

每份文案对应一个项目目录，默认 `~/.digital-human/projects/<日期-哈希前8位>/`（Windows 为 `%USERPROFILE%\.digital-human\projects\...`，可用环境变量 `DH_WORKSPACE` 改根目录）。下文称 `workdir`。里面有：

- `copy.txt`：用户文案原文（一个字不改）；`meta.json`：哈希、字数，以及各环节写回的进度
- `voice.json`、`paragraphs.json`、`cache/`、`out/`（配音、`timeline.json`、`words.json`）

文案去掉空白后哈希相同就算同一份：直接命中缓存、复用已有音频和逐词时间，不重复合成。数字人、包装两个阶段读同一个目录（约定见 `references/pipeline.md`）。用户的默认音色记在根目录的 `voice.json`，新项目不给样本就复用它。

## 红线

- **不改文案。** 文案是用户的，不润色、不增删、不纠错字；发现可疑的地方只在最后提示，由用户决定。
- 其余（是否本人声音、噪声）按用户的要求不询问、不提示，直接做。

## 流程

脚本路径相对本技能目录。

### 0. 查桌面端

```
python scripts/voice/check_key.py
```

（文件名沿用旧版，实际检查的是 JMCAI 桌面端，不是密钥。）

- 退出码 0：桌面端在线、克隆工作流和识别工作流都启用了，继续。
- 退出码 3：本机没连上桌面端，或必需的配音/识别工作流没启用。**不要自己去猜端口或翻配置**，把输出里的引导话转给用户，让他确认桌面端已打开、工作流已启用（端口不是默认的 32100 时，让用户告诉我，我设 `JMCAI_BRIDGE_URL`）。

需要的两套工作流：`qwen3-tts-_api`（或用户选定的另一套 TTS）与 `qwen3-asr-_api`。缺哪套就告诉用户缺哪套。

### 1. 收文案，先缓存

1. 拿到用户的文案（文本或文件）。贴在聊天里的，用 Write 工具原样存成一个临时文件（UTF-8）。
2. 建立或命中项目缓存：

   ```
   python scripts/voice/project.py init --copy <文案文件>
   ```

   输出里有 `project_dir`（后面的 `workdir`）、`cache_hit` 和各环节进度 `state`。**如果 `state.audio` 和 `state.words` 都已有**：告诉用户命中缓存、直接复用，跳到第 6 步交付；用户明确要重做才继续。

3. 人声样本：用户给一段 3–30 秒、干净、无背景音的正常口播（wav/mp3/m4a/flac）。如果已经有默认音色（上次用过），就不用再要，告诉用户"沿用你上次的声音"，用户说要换再要样本。

### 2. 登记音色

本地 TTS 不需要向云端"注册音色"——**参考音频本身就是音色**，每次合成时随请求一起发过去。所以这一步只是把样本收好、记进 `voice.json`：

```
python scripts/voice/clone_voice.py --workdir <workdir> --sample <样本>          # 克隆（默认）
python scripts/voice/clone_voice.py --workdir <workdir>                          # 沿用上次的样本
python scripts/voice/clone_voice.py --workdir <workdir> --sample <新样本> --force  # 换声音
python scripts/voice/clone_voice.py --workdir <workdir> --speaker Serena         # 改用预设音色
python scripts/voice/clone_voice.py --workdir <workdir> --design "低沉、语速慢的中年男声"  # 声音设计
python scripts/voice/clone_voice.py --list                                       # 用过的所有音色
python scripts/voice/clone_voice.py --workdir <workdir> --use 1                  # 换回以前某个音色
```

用户说"还是用上次那个声音""换回 X 月 X 日的"时用 `--list` 找，再 `--use`，不要让用户重新给样本。

样本短于 3 秒时脚本会报错，让用户重新给一段；超过 30 秒会提示（克隆工作流的 `ref_audio_max_seconds` 默认 30，超出部分不参与）。其他情况不拦。

### 3. 通读全文，按大段拆分

先把整篇文案从头读一遍，理解它的结构，再拆。目的是让每一段的情绪稳定，所以：

- **用户的换行就是用户要的分段，按他的分。** 用户贴来的文案已经分好段，就一段一段用，不要再自己合并或打碎；只有某一段超过上限才在它内部再拆。（实际发生过：自己拆成十几小段，用户嫌太碎。）
- **用户没分段时，按话题转折拆成 5–8 个大段，每段 250–500 字，不按句子拆。** 拆得越碎，各段接缝处的语气越容易不连贯，宁可少拆。
- **每段最多 1000 字**；全文不超过 1000 字就整篇一段，不必拆。
- 分段越少，各段语气越一致；分段越多，越方便只重做某一段。各段的语速、音高在核对里会列出来。
- 拆在自然的换气处：话题切换、"第一步/第二步"之间、总起和展开之间；不要在一句话中间断开。
- 一段很短（几十字）时并入相邻段，除非它本身就是独立的开场或结尾。
- 不改字：各段拼起来必须等于原文（空白除外）。

把结果写成 `<workdir>/paragraphs.json`：`{"paragraphs": ["第一段……", "第二段……"]}`，然后把关：

```
python scripts/voice/split_check.py --copy <workdir>/copy.txt --paragraphs <workdir>/paragraphs.json
```

不合格（文字对不上或超 1000 字）就修正后重跑，直到"合格"。不需要停下来等用户确认拆分，拆分结果会在最后的交付里列出。

### 4. 情绪标签（只在 preset / design 模式下），然后合成并拼接

**clone 模式（默认）跳过本节的情绪标签部分**：克隆工作流没有指令参数，标签会被剥掉，写了也没用。直接跑 `synth.py` 即可。

preset / design 模式下情绪标签照旧有用，规则：

- **兴奋 `[excited]` 为主，其他为辅**；一条片子用 1–3 种，不强制。只有文案里确实需要别的情绪时才用：吐槽、委屈、自嘲用 `[sad]`；轻松、调侃、道别用 `[happy]`。拿不准就用兴奋。
- **只加在整句的开头**，不加在句子中间。句中的标签会被原样念出来，也会让一句话内部变调。
- **不要太碎**：一条 1500 字的片子，自己挑的标签大约十来处，落在情绪确实转折或需要强调的句子上。
- **信息密集的地方（报档位、念清单、读提示词）也要有标签，沿用前面的情绪**。这一条脚本自动做：段首必补；段内某句没有标签、且离上一个标签已超过 80 字时补一个沿用的标签；问句标签只管问句那一句。
- 问句前的 `[curious]` 照旧自动加，不算情绪标签、不占 1–3 种。

做法：复制 `references/voice/emotions.example.json` 到项目目录，改名 `emotions.json`，通读文案，按上面的规则把 `tags` 填好（`at` 写那一句开头的几个字，必须是整句的开头；同样的字出现多次时用 `n` 指定第几次）。可选项：`carry` 写 `auto`（默认）、`sentence`、`paragraph`、`off`；`carry_gap` 默认 80；`instruction` 可以覆盖整体描述；`question_tag` 写成 `""` 则连问句标签也不加。

先看一眼实际发出去的文字，不提交、不花时间：

```
python scripts/voice/synth.py --workdir <workdir> --dry-run
```

它会打印每段带上所有标签后的文字、标签总数、没匹配上的规则，以及不在句首的标签（有就改掉）。确认后再合成：

```
python scripts/voice/synth.py --workdir <workdir>
```

- **内置声学门禁与自动抽卡（Auto-Reroll）**：本地克隆（clone 模式）时，隐空间随机种子可能导致个别段落出现发尖变调、语调僵硬的"坏卡"。脚本默认开启 `--acoustic-gate`：
  - 合成每段后自动提取 13 维 MFCC 音色特征与 pyin F0 基频中位数，与登记时的参考音频基准比对；
  - 若 MFCC 距离 > 0.20 或 F0 偏离基准 > 25%，自动换随机 seed 原位重新抽卡（默认最多重抽 3 次，`--max-rerolls 3`）；
  - 若达到最大重抽次数仍未达标，启动 **Best-of-N 兜底机制**，自动挑选历次尝试中综合惩罚最小的最优版本落盘；**采纳的最优版本会写回"默认种子"那个缓存槽位**（重抽产生的候选在各自的 key 下，不写回的话下次重跑会命中第一次被门禁判掉的那张坏卡——实跑踩过：段1 第 1 次 MFCC 0.2924、第 4 次 0.2010，重跑别段时段1 从缓存拿回了 0.2924，整条片子的音色被悄悄拉低）；
  - 若命中历史缓存但检测到该缓存音色偏离过大（旧版坏样本），也会自动触发重抽；
  - 不想用门禁可加 `--no-acoustic-gate`；微调阈值可用 `--mfcc-threshold 0.20` 与 `--f0-threshold 0.25`。
  - **语调动态（只提示，不拦截）**：MFCC 和 F0 中位数只能说明"音色像不像"，测不出"语调是不是发僵"——发僵的段常常中位数完全对、但基频几乎不动。所以还会比 `f0_std`（基频起伏）和 `rms_std`（能量起伏）相对参考的比值，低于 0.70 就提示"语调偏平"。实测正常配音的这个比值在 **0.85–1.15**。念清单、报参数本来就该平，看到提示自己判断，不影响出片。
  - **改过 `synth.py` / `acoustic_gate.py` 之后跑一遍 `python scripts/voice/selftest.py`**：它不联网、不需要桌面端，用假的合成和假的门禁结果把"判定、抽卡循环、缓存键、最优候选写回、拆段、wav 读写"验一遍（30 项）。这套循环的错法很隐蔽——比如某次改动让"全不过时取最优候选"退化成"取最后一次"，实跑里只会表现为音色偶尔差一点，不看代码发现不了。
- **默认串行 1 路**：算力是单张卡，同时提交只会互相排队。确实要并行时设环境变量 `DH_TTS_WORKERS=2`。
- 结果按"文字+音色+模式"缓存，重跑只补变动或失败的段。
- **标签引出来的多余语气词会自动剪掉**（preset/design 模式才有）。句首的情绪标签有时会让模型在句子前多"呼"出一声（嘿、哼、哎、哈……），文案里并没有。所以标签照常加，合并之前由 `scripts/voice/fillers.py` 处理：对每一段识别一次，和原文逐字比对，只找"多出来"的语气词（原文自己有的"哼！""哦对了"不动），按音频能量找到这一声的起止，连同多出来的停顿一起剪掉（前后停顿合计留 0.5 秒内），剪完再识别一遍确认语气词没了、原文的字没少；验证不通过就保留原样并报告，不冒险。结果在合成输出里以"剪掉多余语气词 段N：X 秒处'嘿'，已剪掉"列出，交付时要告诉用户剪了哪几处。不想剪用 `--keep-fillers`。
- 问句标签只认问号：句子以"？"结尾才会带疑问语气。通读文案时如果看到明显是问句却用了句号的句子（例如"你有没有遇到过……。"），**不要替用户改**，在交付时列出来。
- 产物：`out/merged.wav`（段间停顿 0.3 秒、首尾已去多余静音）、`out/seg_NN.wav`、`out/timeline.json`（每段起止秒和首部裁剪量）。
- **重新合成出了不同的结果时，上一版自动存到 `out_prev/<时间>/`**。想另出一版又不覆盖：`--variant 名字`，结果写到 `out_名字/`。
- 退出码 5：`merged.wav` 被别的程序占用（多半是用户正开着播放器），新的已另存为 `merged_新.wav`。
- 有段失败时不会拼接；把失败原因原样告诉用户。合成失败会退避重试 6 次（本地任务偶尔要排队几分钟，不是出错）。

### 5. 逐字对齐与核对

```
python scripts/voice/align_words.py --workdir <workdir>
python scripts/voice/verify_audio.py --workdir <workdir>
```

- `align_words.py`：对每段调用 Qwen3-ASR 工作流，得到**字级**起止时间，写入 `out/words.json`（时间在 `merged.wav` 的时间轴上，单位秒）；同时用音频能量找出停顿（≥0.25 秒），供后续分段和动作编排使用。
- `verify_audio.py`：把识别出的文字和原文比较（去标点、统一数字写法后），并输出全篇各段与参考音色的多维量化核对表（字数、时长、字速、F0 差值、MFCC 距离、声学得分、文字相似度、门禁状态），给出全片音色一致性综合评分。
- 识别返回的是**字级**时间（工作流每行一条 `起始-结束: 字`），与旧版百炼的"词级"不同；字与字首尾相接，所以停顿仍然用音频能量检测，不要从字间隙里找。
- 识别结果偶有同音字出入，相似度低于 0.9 的段落会标出，请用户听那一段。
- 品牌词（如 JMCAI）每次、每段的读法都可能不一样，识别结果会写成 JMC AI 等；这是读法不稳，不是漏读。交付时提一句，让用户听。

### 6. 小结并进入下一阶段

一条龙流程里这一步不是终点：用下面的要点向用户报一句进度，然后进入数字人阶段。**例外**：用户在开头选了"配音做完先让我听"，或者只要配音，就在这里停下，等他说可以再往下做。

先给结论，再给依据，用中文：

- 一句话结论：配音已生成，几段、合计几秒，文件在哪，项目目录在哪。
- 列出拆段结果：每段的字数、起止秒和开头几个字。
- 核对结果：文字是否一致、各段语速音高有没有被标出（列一张各段的时长、语速、音高表，最慢和最快的段点出来）。
- 情绪标签：如果用了，说明哪几种、几处；clone 模式下说明情绪来自参考音频。
- 问句：有几句加了疑问语气；有没有像问句但没用问号的句子。
- **没验证的**如实写：没听过音频就说明只做了数据核对，请用户试听。

## 失败时怎么办

| 现象 | 做法 |
|---|---|
| 退出码 3 | 桌面端没连上或工作流没启用，走第 0 步 |
| 退出码 4 | 桌面端在算力目标上执行失败，把原始错误转给用户 |
| 某段重试 6 次仍失败 | 报告原始错误；其余段已缓存，修好后重跑只补这一段 |
| 任务排队很久 | 本地/远端单卡串行，前面还有别的任务在跑；等就是了，脚本会一直轮询 |
| 找不到 ffmpeg、缺某个 Python 包 | 运行 `python scripts/setup_env.py --stage voice` 自动装上，再重试 |
| 识别没有返回字级时间 | 报告原始返回，不用估算冒充；让用户知道逐词时间缺失 |

工作流的输入输出契约、实测结论，见 `references/voice/api-notes.md`。桌面端前置条件见 `references/voice/onboarding.md`。`out/words.json` 和 `meta.json` 是给后续数字人环节用的：分段只能在 `pauses` 里断开，动作编排按 `words` 的时间对齐。
